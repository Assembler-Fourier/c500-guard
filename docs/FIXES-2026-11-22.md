# Seven QA repairs — 22 November 2026

This release repairs the seven defects reproduced in the independent QA. It preserves the ten-second acknowledgement quiet period, one-second keyboard/mouse guard, pedestrian manual-acknowledgement policy, lane sounds, existing camera zones and calibration.

## Repairs

| Finding | Resulting behavior |
|---|---|
| D1: following car silently consumes the lead car's acknowledged visit | Previously co-visible vehicles remain separate visits. A follower that confirms after quiet expires can raise its own alarm. Separation is also captured on the frame that first creates a visit. |
| D2: full-frame focused pixels unavailable to the optional entrance verifier | Reuse the existing full-frame focused input when context checking is enabled, retaining source/freshness/epoch checks and avoiding an extra primary pass. |
| D3: display rounding admits a below-threshold detection | Admission and strong continuation checks use raw decoder confidence with matching float32 thresholds. Display rounding is unchanged. |
| B1: changing sound settings resets reminder timing | Every audio reset restores the configured reminder period; combined sound/period saves regenerate the asset once with both choices applied. |
| B2: acknowledging another arm during UNKNOWN loses an earlier mute | Mute identities survive uncertain readings and another arm's acknowledgement. A genuinely new up-period can remind again. |
| B3: contradictory angle evidence sustains an up reminder | Contradictory observations cannot establish or refresh eligible UP memory; both reminder paths require compatible evidence for the same arm. |
| B4: partial profile save claims success | Receipts distinguish locally applied choices from failed profile copies. Both interfaces show a retry carrying the exact intended values, including OFF. Saved choices remain authoritative when switching profiles. |

The expanded review also repaired a rapid-queue case where a departed lead's dormant track stole the following vehicle's detection. A narrow motion reservation applies only with prior co-visibility, recent strong forward motion and strong predicted overlap. Ordinary association remains the fallback. Camera-profile switching defers without side effects when settings are busy, avoiding an inverse lock order.

The initial complete private/public runs each had eight failures in JavaScript test harnesses. Six extracted a newly added event listener without its DOM; two omitted a new transport global. Function extraction boundaries and test globals were corrected; all 14 existing methods and 92 JavaScript assertion fragments in the two affected files were retained. No application code changed between the large traffic run and the final full suites. The initial failed logs remain local. The final complete reruns above passed.

Public skips retain the original optional/private-fixture assertions: 42 labelled scene fixtures, two private PTZ incidents, one private reference, one model smoke-image opt-in, and two real app-lifecycle opt-ins. Private-suite skips are its four optional smoke/reference/app checks as recorded by that runner. No live OFF/F4 exercise is claimed.

The virtual traffic tool uses eight deterministic scenario families with randomized positions, classes and confidence: ordinary entrance/exit arrivals, pedestrian attention, a following car after quiet, a follower waiting through quiet, short occlusion, rejected weak/outside/stale observations, and two pedestrians. Its virtual clock skips idle periods after sampled fresh clearance. It tests actual tracker, visit memory and alarm/acknowledgement decision methods with supplied detections and fake output services. It does **not** run thousands of hours of video, measure detector recall, verify physical audio, or exercise the complete live frame loop. Separate regression tests cover the one-second input guard, pedestrian latch, automatic service acknowledgement and barrier interactions.

Before/after reproductions increased the missed-follower case from one to two alarms, and both slow and rapid three-vehicle cases from one to three alarms. Four retained real-model observation sequences (432 observations) preserved every track ID and first-event time. This is a regression comparison using cached detections, not fresh model inference or an independent accuracy benchmark.

## Deployment and limits

Installed 12 allowlisted source/test files with verified backups and a supervised refresh. Installed SHA-256 hashes match the tested stage. Alerts remained **armed**, matching the pre-refresh state. The final operational sample had fresh camera/input/AI data and no fault; the one-second input guard and ten-second quiet period were unchanged. The generated reminder WAV is 10 seconds, matching the configured period. Active configuration and nine of ten monitored runtime archives retained their hashes, including every barrier template and the primary alignment reference. The existing startup learner refreshed one lighting-reference cache at 01:16:18; its logged update, unchanged learning methods and six valid reference arrays were reviewed and its exact new hash was accepted. The initial blanket hash-check failure is retained. Served dashboard/settings pages contain the new retry flow.

The two-second entrance test was accepted, playback was observed starting and stopping without an error, and speaker volume returned to its prior value. Human audibility was not confirmed.

The editable UI source is synchronized to the tested bundle before publication; future builds must use `tools/build_ui.py` from a development checkout. Physical vehicle arrivals and speaker audibility are not established by simulated alarms or an accepted test-tone request.

No model was trained or replaced, no dependency was added, and the installer changed no barrier calibration or zone geometry. The existing startup lighting learner refreshed one appearance-reference cache, as recorded above. Physical barrier classification under new lighting, missed model detections under severe glare/weather, full-night reliability and a native optional inference call that hangs remain unproven. Optional inference is still serial with primary publication; an execution exception can still disable that optional verifier until reconstruction. Pending profile-copy warnings are process-local, although the active reminder choices are durable and protected across a restart/view switch.

Private recordings, calibration, camera configuration, raw operational logs and vehicle records remain excluded. The historical [QA report](QA-2026-11-22.md) records the original failures; [research priorities](UPGRADE-RESEARCH-2026-11-22.md) remain relevant for future measured upgrades.
