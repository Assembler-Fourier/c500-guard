c500-guard — Deployment Runbook

Barrier/gate camera alarm · Windows 24/7 deployment · every error hit during build, with its cause and fix
Repository: Assembler-Fourier/c500-guard (private) · Generated 2026-09-07

Alarm only. This system never operates the barrier, gate or any powered equipment. Barrier operation stays manual under the site's approved procedure. Ireland's HSA warns that powered gates can cause fatal crushing injuries and that remote operation without adequate sight is particularly hazardous.

1. What this is

A local intruder alarm. It watches the camera feed, sounds a siren that does not stop until a human acknowledges it, and turns on and off with one global hotkey. Everything runs on one machine. No cloud service, no phone kept busy, no notifications to miss.

Xiaomi C500 ──LAN──> go2rtc bridge ──rtsp://127.0.0.1:8554/c500──> watcher ──> siren │ Ctrl+Alt+F4 ──────────┘ on / off
PieceWhat it doesPort

The web page belongs to the watcher. If the watcher stops, http://127.0.0.1:8787 goes dead. That is not a separate fault — start the watcher and the page returns.

2. Windows installation

2.1 Get the code

winget install --id GitHub.cli -e
gh auth login
gh repo clone Assembler-Fourier/c500-guard C:\c500-guard

Install to a permanent path such as C:\c500-guard. The autostart tasks bake in the path — do not leave it in Downloads.

2.2 Sanity-check before executing (optional, 5 seconds)

$e=$null; [System.Management.Automation.Language.Parser]::ParseFile("$PWD\install.ps1",[ref]$null,[ref]$e); $e

Prints nothing = syntactically clean.

2.3 Install

PowerShell as Administrator, in that folder:

Set-ExecutionPolicy -Scope Process Bypass -Force
.\install.ps1

It installs Python and ffmpeg if missing, builds the virtual environment, downloads go2rtc and verifies it against a pinned SHA-256, and registers two scheduled tasks that run at logon with highest privileges and restart on failure. Safe to re-run at any time.

Elevation is required, for two reasons: registering the autostart tasks, and the keyboard hook. A hook installed by a non-elevated process cannot see keystrokes while an elevated window has focus — giving you a hotkey that works most of the time, which is worse than one that always works.

Remove autostart later with .\install.ps1 -Uninstall.

2.4 Connect the camera — once

.\.venv\Scripts\python.exe src\bridge.py start
.\.venv\Scripts\python.exe src\bridge.py login-details

Open the printed URL, scroll to Xiaomi, sign in. Two traps below cost hours during the build — read section 4 before you start.

Verify: bridge.py status must show "streams": ["c500"].

2.5 Draw zones for your camera

.\.venv\Scripts\python.exe src\watch.py snapshot rtsp://127.0.0.1:8554/c500 --out snapshot.png

That writes a still with a labelled 0–1 grid. Read corners off it into config\zones.json as [x, y, width, height].

Exclude anything that changes by itself. An on-screen clock inside a zone fires the siren every single second. In this deployment the ANPR clock sits at roughly x 0.40–0.60, y 0.08–0.12, and a second HIKVISION monitor occupies x < 0.36. Both are excluded.

2.6 Run

.\.venv\Scripts\python.exe src\ctl.py start
.\.venv\Scripts\python.exe src\ctl.py doctor

Then open http://127.0.0.1:8787. After a reboot both watcher and hotkey start on their own.

The three tones — deliberately impossible to confuse

ToneSoundMeans
MAINSwept siren, 620→1650→620 Hz, continuous, loops seamlessly Something moved in a zone. Latched until acknowledged.
EARLYThree fast rising chirps, quieter Sudden brightness — headlights. Upgrades to MAIN if motion confirms.
FAULTSlow low warble, 385/280 Hz Feed lost, frozen or black. Not a detection.
If you hear the low warble, nothing walked past. The feed is broken — go to section 4.7.

The on/off key

Ctrl+Alt+F4 toggles the whole system from any window. The keystroke is swallowed by the hook when it matches, so it can never reach the foreground app as Alt+F4 and close a window.

  • Turning ON plays a short rising two-note confirmation.
  • Turning OFF is silent — while off the system makes no sound at all. Add --beep-both to the hotkey task if you want confirmation both ways.
  • While off: no siren, no chirp, no fault tone, no notification, and nothing written to the event log except the single disarmed line. It keeps decoding video so it is instantly ready.
  • The off state is stored in armed.json and survives reboots. Switched off on Friday means still off on Monday. ctl.py doctor will say so.

Acknowledging does not stop detection

It silences the current alarm only. The next rising edge in any zone re-triggers immediately, so two arrivals seconds apart both alarm. There is no cooldown that could swallow the second one.

4. Every error hit during the build, and its fix

4.1 Xiaomi login fails with code 70016

{"code":70016,"description":"登录验证失败","captchaUrl":null,"securityStatus":0}

Cause: using an email address as the username. If the Xiaomi account's identity is a phone number, the email is only a recovery address and Xiaomi rejects it as a sign-in identity. captchaUrl:null and securityStatus:0 confirm it is neither a captcha nor 2FA problem — the credential pair was rejected outright.

Fix: use the numeric Mi Account ID. Sign in at account.xiaomi.com and read it from the page URL: userId=1234567890. If that fails too, try the full phone number with country code.

4.2 Login succeeds but "no sources"

Cause A — wrong region. Devices live in exactly one Xiaomi region. The wrong pick returns an empty list after a perfectly good login. Check all six rather than guessing:

curl -u c500-local:PASSWORD "http://127.0.0.1:1984/api/xiaomi?id=YOUR_ID®ion=de"
# regions: cn  de  i2  ru  sg  us

Cause B — the camera is on a different Xiaomi account, or is shared to you rather than owned. During the build all six regions returned empty until the camera was re-registered to the account being used. In this deployment the correct region is de (Europe).

An offline camera is still listed. So "no sources" never means "the camera is unplugged" — it means the camera is not on this account.

4.3 The go2rtc Add page 404s

Cause: the page is /add.html, not /add.

Fix: http://127.0.0.1:1984/add.html

4.4 Streams vanish after restarting the bridge

yaml: line 32: did not find expected ',' or '}'

Cause: the config was written as a JSON object, and go2rtc appends its Xiaomi session as YAML after the closing brace. go2rtc can read that hybrid but cannot save to it — so every stream you add is lost on restart, silently.

Fix: already handled — bridge.py writes real YAML and repairs a hybrid automatically. To repair manually: bridge.py repair-config (keeps a timestamped backup).

4.5 ffmpeg cannot open the RTSP stream

Error opening input: Invalid data found when processing input

Cause: passing -timeout to the RTSP demuxer. In ffmpeg 7+ that option means listen timeout and implies listen mode, which breaks an outgoing connection. (The older -stimeout was removed.)

Fix: already removed from the code. The reader has its own stall watchdog instead.

4.6 A FAULT fires seconds after starting, with no camera problem

FAULT — no usable frame for 5s

Cause: RTSP needs several seconds to connect and wait for a keyframe, but the feed-lost threshold is 5 seconds. Startup tripped its own fault before the first frame arrived.

Fix: already handled — a 30-second --connect-grace applies until the first frame lands; the 5-second threshold only applies once video is flowing. A genuine startup fault now reads ... since startup.

4.7 A genuine FAULT: feed dies during operation

read udp [::]:60392: i/o timeout
Post "https://de.api.io.mi.com/.../miss_get_vendor": context deadline exceeded
Server returned 404 Not Found

Cause: the machine was no longer on the camera's network. During the build the Mac had switched to an iPhone hotspot (172.20.10.x) while the camera sat on 192.168.1.x. Internet worked fine, which is what makes this confusing.

Diagnose:

ipconfig                       # Windows - check the IPv4 address
ping 192.168.1.23              # the camera

Fix: rejoin the camera's network. The watcher reconnects on its own within seconds; then acknowledge the latched fault.

Structural weakness worth knowing: the Xiaomi route needs two things at once — internet reachability to Xiaomi's cloud (for the camera keys) and the camera on the same LAN. A plain ONVIF/RTSP camera needs only the second, and is the more robust choice long term.

4.8 The bridge refuses to restart

Port 1984 is already served by another process.

Cause: after a stop, the socket lingers in TIME_WAIT for about 30 seconds. A bind() test fails during that window even though nothing is listening.

Fix: already fixed — the check now attempts a TCP connect, so it only reports occupied when something genuinely accepts. If you see this message now, something really is on the port:

netstat -ano | findstr :1984          # Windows: find the owning PID

4.9 The system crashed when switched back on

TypeError: 'NoneType' object is not subscriptable

Cause: a race. The arm/disarm call runs on the web/hotkey thread and was resetting the detector's background frame while the detector thread was mid-calculation. With a hotkey this killed the watcher every time it was re-armed.

Fix: already fixed — the hotkey thread now only raises a flag, and the detector performs the reset at a safe point. Verified with twelve rapid toggles: no crash.

4.10 The web page is dead

Cause: the page is served by the watcher process. No watcher, no page.

Fix: ctl.py start, then reload.

4.11 The camera cannot be found by scanning the network

Cause: Xiaomi cameras answer on proprietary ports. A scan of 80/443/554/8554/5000/6668 finds nothing even when the camera is present and healthy. During the build this produced a wrong conclusion that the camera was absent — it was at 192.168.1.23 the whole time.

Fix: trust the go2rtc device list, not a port scan. The device entry reports the real IP and MAC.

4.12 The siren fires constantly with nothing there

Cause: a zone overlaps something that changes on its own — an on-screen clock, a screen edge, foliage, or a large exposure swing at dawn.

Fix: re-run snapshot, shrink the zone away from it, or raise motion_pct. For dawn/dusk exposure specifically, raise light_delta.

Fault thresholds

ConditionDefault
No frame → FEED LOST5 s (30 s before the first frame ever arrives)
Byte-identical frames → FROZEN20 s
Black picture5 s

Freeze detection requires byte-identical frames, which real sensor noise never produces. A quiet but live scene is therefore never mislabelled as frozen.

Verification checklist before relying on it

  1. ctl.py doctor — all checks pass
  2. ctl.py test-alarm — all three tones audible from the guard position
  3. Walk the approach on foot; confirm the siren and check events.jsonl
  4. Drive a vehicle through; confirm detection and timing
  5. Unplug the camera; confirm the FAULT warble within ~5 seconds
  6. Press Ctrl+Alt+F4; confirm silence, then again and confirm it detects
  7. Reboot; confirm both tasks come back and the armed state is preserved
  8. Run a daylight shift alongside the manual process; log misses and nuisance alarms

6. Honest limits

  • Change detection, not object recognition. It fires on rain, cats, wipers and large exposure swings as readily as on cars. Zones and thresholds are the only discrimination. If daylight proves too noisy, the next step is a YOLOX/ONNX person-and-vehicle classifier behind the same zone logic.
  • Model support is unofficial. xiaomi.camera.c302o works through go2rtc v1.9.14 despite not appearing in the project's confirmed-model list. A future firmware or go2rtc update could break it.
  • It cannot alert you if the machine loses power, or the speaker is muted or unheard. That is why the test-alarm step exists.
  • The Windows-specific code was written but never executed by its author — the keyboard hook, the installer, the scheduled tasks, winsound audio and gdigrab capture were all developed on macOS. Expect to fix something on first run; the cross-platform logic is tested, the Windows bindings are not.
  • Barrier operation stays manual. Nothing here opens a gate.
