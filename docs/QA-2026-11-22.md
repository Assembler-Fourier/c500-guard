# Independent QA — 22 November 2026

**Seven defects reproduced; no fixes applied in this audit.** The highest-priority finding can suppress a distinct following vehicle after the acknowledgement quiet period has expired. Passing the existing suite does not cover these adversarial cases.

Three independent reviewers examined detection/visit handling, barrier/reminder behavior, and comparable systems/publication. The reviewed implementation includes the 21 November reliability work, dashboard refresh, native title-bar change and latest barrier-reminder release. Tests used disposable state, synthetic frames/detections and fake inference/audio. Operational controls and settings were left unchanged. No camera footage or calibration is published.

The ten-second acknowledgement quiet period and one-second keyboard/mouse guard remain intentional. They are not proposed changes and do not explain the follower defect below.

### D1: follower suppressed by an acknowledged visit

`observe()` remembers independently co-visible tracks in `separate_tracks`. The unanswered-continuation path respects that distinction, but geometric reidentification in `consider()` does not. When the lead track disappears, a same-family follower overlapping its recent box can be aliased to the acknowledged lead visit.

The isolated sequence used the actual tracker: lead track 1 was acknowledged at t=3.25; quiet would end at t=13.25. Follower track 2 confirmed at t=14.5 after two fresh stop-line observations, moving toward the gate. The memory already recorded track 2 as separate, yet returned the acknowledged first visit and `suppress=true`. A separate probe of the actual alarm method returned `True`, left `alarm=None` and made zero fake audio calls. The caller treats that return as consumed and marks the event emitted.

**Future acceptance:** a separately observed follower must receive a distinct visit/alarm after quiet expires, including when the lead disappears before the follower confirms. Repeat with manual and automatic acknowledgement, unanswered lead alarms and three-observation confirmation. Same-car occlusion recovery must still avoid duplicate alarms.

### D2: whole-frame pixels rejected as missing context

The input builder avoids appending a duplicate context view when a focused crop already covers the full image. The optional verifier accepts only a view tagged `context`, so it rejects these otherwise sufficient pixels. Three synthetic full-frame packets produced three primary calls and zero secondary calls, with a misleading missing-picture/region diagnostic.

This is conditional on crop configuration; it was not observed in the active PTZ crop. **Future acceptance:** reuse a full-frame focused input for one optional check without adding a redundant primary call or counting one frame as multiple temporal observations. Preserve source, epoch, region and freshness gates.

### B1: saved audio style changes the reminder period

Reloading audio settings resets module defaults, including the reminder period, to fifteen seconds. A sound-style save regenerates WAV assets without restoring the configured barrier reminder period. In scratch storage, a ten-second WAV became fifteen seconds while saved settings and runtime barrier rules still said ten. No audio was played.

**Future acceptance:** all alarm-setting updates retain the configured reminder interval in both metadata and regenerated assets, including nondefault intervals.

### B2: another arm's acknowledgement loses an earlier mute

Acknowledgement replaces the complete mute map with arms seen UP in the last five seconds. An already-muted exit arm temporarily reading UNKNOWN is omitted when an entrance reminder is acknowledged. When the exit returns to the same UP period, it sounds again despite never having been confirmed closed. The isolated probe exercised actual acknowledgement, observation and reminder methods with fake audio.

**Future acceptance:** preserve muted period identities through temporary UNKNOWN and merge newly acknowledged arms. Rearm only after a confirmed period change or explicitly documented reset.

### B3: UNKNOWN display and sounding reminder disagree

When strict classification and remembered position agree on UP, `_note_arm_memory()` refreshes freshness before consulting the independent angle tracker. A fresh angle conflict changes the display to UNKNOWN but does not prevent the memory-based reminder. Repeated conflicts can therefore keep it eligible indefinitely. The separate service-cycle reminder was disabled in the probe, establishing which path generated the sound.

**Future acceptance:** reminder eligibility uses reconciled fresh evidence, with history kept separately. Test both persistent and temporary angle conflicts. No unintended automatic acknowledgement was demonstrated by this finding.

### B4: profile synchronization failure hidden from the caller

Individual profile writes are atomic, but a profile-write exception is logged and swallowed while the settings API returns `ok=true`. Injecting one synthetic write failure left the active profile and one saved profile OFF while another remained ON. Loading the stale profile could restore the old choice.

An explicit identical-value retry after removing the fault **did repair all profiles**. An initial hypothesis that retries were ignored was disproved. **Future acceptance:** expose partial-save status and test every write-failure position plus subsequent profile loading and retry.

### D3: confidence rounding at a stricter region boundary

The decoder preserves a raw score while rounding the display score to four decimals. The monitor filters on raw confidence, but a stricter per-region floor compares rounded confidence. With another region allowing candidates below that floor, raw `.69996` / displayed `.7` passed a `.7` region and produced an event after two observations. The gap is below `.00005`; this is not claimed as the cause of a real false alarm.

**Future acceptance:** use consistent raw comparisons when available, preserving legacy adapters without raw scores and unchanged display rounding.

## Additional reliability and validation gaps

- **Secondary recovery policy:** an injected transient exception permanently disables the optional verifier until the primary worker is rebuilt or restarted. Healthy primary inference continues and secondary health shows unavailable. This behavior is already encoded in existing tests; it is a recovery-policy limitation, not a newly introduced regression. A successful but slow optional call follows a different, recoverable cooldown path.
- **Native stalls:** the optional call remains synchronous before publication of primary results. Its post-return budget is not cancellation of a hung native call. Historical multi-second stalls were not reproduced or resolved in this audit.
- **Accuracy denominator:** alarm-triggered clips alone cannot measure missed arrivals or false alarms per operating hour. Independent labelled time windows and quiet controls are needed.
- **Barrier evidence:** synthetic tests do not establish real UP/DOWN accuracy through glare, weather, occlusion or a changed camera pose. A balanced held-out state set is still needed.
- **Operational checks:** no physical barrier actuation, live speaker test, real-camera lifecycle test, Full OFF/F4 test or unattended overnight trial was performed. Existing lifecycle tests use isolated/fake services or explicit skips.
- **Documentation drift:** some installed historical notes describe obsolete controls and timing. This publication provides a new verification checkpoint; old notes must not be used as runtime proof.

## Evidence and limits

The frozen existing implementation ran **2,001 tests: 1,997 passed and 4 skipped**, in 325.593 seconds of unittest execution. Its source/config snapshot hashes were unchanged afterward. Scoped reviewer checks passed 73 detection tests and 221 barrier tests; these overlap the full suite and must not be added to its total.

Seven adversarial probes reproduced the defects above. A successful probe means the defect was demonstrated, not fixed. Private scripts, synthetic traces, transcripts and source hashes are retained outside the public repository. Public source-package tests are a separate run recorded in [current deployment verification](current-deployment.md); sanitization retains test definitions and assertions, with private-fixture tests explicitly skipped when evidence is absent.

Read-only operational sampling found an armed, healthy primary and secondary pipeline, fresh DOWN readings for both arms and no reported fault. This observation does not exercise the failing scenarios or establish future availability.

Follow-up design experiments and measurable acceptance criteria are in [upgrade research](UPGRADE-RESEARCH-2026-11-22.md). All findings remain open in this source publication.
